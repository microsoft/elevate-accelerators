### Reading The Evidence CSV

- Unique key: `source`, `interface`, `entity`, `field`. Canvas REST `entity` is `resource::Model`, for example `submissions::Submission`; this prevents conflicting declarations in different resources from being silently combined.
- `type` is the declared type, not inferred from an example. `format` preserves declared formats. `$ref` and array-item references are in `reference`; a reference-only property has `type=unknown` when no type is declared.
- `nullable=unknown` means the schema did not explicitly declare it. A missing `required` entry does not establish nullability. Explicit required properties are marked `true`; SIS footnotes marked with an asterisk are `conditional` and require reading the source condition. Other requiredness is conservatively `unknown`.
- `evidence_sha256` hashes the fetched source document bytes. `version` identifies live official Swagger or SIS documentation, **not** a tenant version. The CSV is the captured field inventory; raw downloaded documents were not added to the workspace, and a hash alone cannot reconstruct them.
- Four declarations have no enumerated properties and therefore no field rows: `course_reports::ReportParameters`, `quiz_submission_user_list::QuizSubmissionUserList`, `quiz_submission_user_list::QuizSubmissionUserListMeta`, and `quiz_submission_user_list::JSONAPIPagination`. These are not evidence of empty real responses.
- Swagger model enumeration does not inventory every request parameter, anonymous response example, dynamic dictionary key, or optional association emitted by implementation. Analytics response examples and submission-history includes still need their endpoint documentation.
- The live Submission Markdown example and Swagger model were compared directly: **31 fields in each, with identical field names**. This spot check does not establish global documentation parity.

## Submissions And Grades

Official [Submission REST documentation](https://developerdocs.instructure.com/services/canvas/resources/submissions.md) and [Submission Swagger](https://canvas.instructure.com/doc/api/submissions.json) establish these read paths:

- `GET /api/v1/courses/:course_id/assignments/:assignment_id/submissions` lists assignment submissions.
- `GET /api/v1/courses/:course_id/assignments/:assignment_id/submissions/:user_id` retrieves one student's submission. Here the final path identifier is **the user ID**, not a standalone submission ID.
- `GET /api/v1/courses/:course_id/students/submissions` supports course-scoped collection with documented student/assignment filters. Course-section variants exist; use the documented scopes for the chosen route.

The complete 31-field declared Submission model is: `assignment_id`, `assignment`, `course`, `attempt`, `body`, `grade`, `grade_matches_current_submission`, `html_url`, `preview_url`, `score`, `submission_comments`, `submission_type`, `submitted_at`, `url`, `user_id`, `grader_id`, `graded_at`, `user`, `late`, `assignment_visible`, `excused`, `missing`, `late_policy_status`, `points_deducted`, `seconds_late`, `workflow_state`, `extra_attempts`, `anonymous_id`, `posted_at`, `read_status`, `redo_request`.

1. Preserve snapshot grain `(tenant, course, assignment, user)` and separately attempt grain `(tenant, assignment, user, attempt)`. Regrades can change the same attempt; attempt number alone is not a grade-history version. Raw APIs elsewhere can expose other submission identifiers, but this object and URL contract must not be assigned a guessed `id`.
2. Request `include[]=submission_history` when needed. Optional `submission_comments`, `rubric_assessment`, and other includes are separate payload contracts, not evidence that the default 31-field model fully represents history. Verify attempt visibility and completeness with authorized examples.
3. **Do not request `include[]=read_status` for a passive analytics pull**: the documentation says that including it marks submissions as read. GET does not guarantee absence of side effects.
4. Preserve both numeric `score` and display `grade`. `grade_matches_current_submission=false` indicates a resubmission since grading. Do not mark that current attempt graded solely because an older grade exists.
5. `grader_id` is explicitly nullable when ungraded and can be negative for automated grading. It is not always a valid foreign key to a human teacher. `posted_at` can be nil for unposted grades. Do not expose unposted, anonymous, or moderated grading data through learner-facing Silver views.
6. `excused`, `assignment_visible`, `late`, `missing`, `late_policy_status`, `seconds_late`, and `points_deducted` are material source facts. Preserve them and the observed effective due date. Missing work is not simply `submitted_at IS NULL`; an assignment may be unpublished, unassigned, excused, unavailable, not yet due, externally submitted, or grade-only.
7. Do not compute percentage when the maximum is null, zero, or semantically nonnumeric. If a valid points-based denominator exists, retain its value/version along with the derived percentage. Extra credit can exceed 100%; do not silently clamp it. Letter/pass-fail/GPA-scale grades need their own grading scheme.

[Enrollment grades](https://developerdocs.instructure.com/services/canvas/resources/enrollments.md) include `grades.current_grade`, `grades.current_score`, `grades.final_grade`, `grades.final_score`, `grades.current_points`, and unposted variants. Additional Enrollment properties include override and grading-period totals. Current-versus-final totals differ in treatment of ungraded work; overrides, weights, drop rules, grading periods, and posting policies can further alter the result. Keep source totals in a proposed **CourseGradeSnapshot**, not `AssignmentSubmission` or a MAP-like `AssessmentResult`. [Grading periods](https://developerdocs.instructure.com/services/canvas/resources/grading_periods.md) are not equivalent to enrollment terms.

[Grade-change log](https://developerdocs.instructure.com/services/canvas/resources/grade_change_log.md): `GET /api/v1/audit/grade_change/courses/:course_id` and assignment/student/grader variants expose `GradeChangeEvent.id`, `created_at`, `event_type`, `grade_before`, `grade_after`, `excused_before`, `excused_after`, `graded_anonymously`, `version_number`, `request_id`, and `links`. [Gradebook history](https://developerdocs.instructure.com/services/canvas/resources/gradebook_history.md) has `/api/v1/courses/:course_id/gradebook_history/feed` and day/grader/assignment paths with `SubmissionVersion` and `SubmissionHistory`. These are separately authorized history interfaces, not guaranteed unlimited archives or a substitute for assignment-attempt retention.

## Engagement, Completion, And Extraction

- [CourseProgress](https://developerdocs.instructure.com/services/canvas/resources/courses.md): `GET /api/v1/courses/:course_id/users/:user_id/progress` exposes `requirement_count`, `requirement_completed_count`, `next_requirement_url`, `completed_at`. A ratio is a derived completion measure only when the denominator is valid; it is not mastery or time-on-task.
- [Module completion](https://developerdocs.instructure.com/services/canvas/resources/modules.md) uses student-specific module state and item `completion_requirement`. Do not apply the integration user's completion to all learners. Completion history requires snapshots; a current result is not an event log.
- [Analytics](https://developerdocs.instructure.com/services/canvas/resources/analytics.md) includes `GET /api/v1/courses/:course_id/analytics/activity`, `/analytics/student_summaries`, and `/analytics/users/:student_id/activity`. Response examples include `page_views` and `participations`; these are aggregates with documented bucket shapes, not universal event-level schemas. Preserve the endpoint, time bucket, timezone, and grain.
- [PageView](https://developerdocs.instructure.com/services/canvas/resources/users.md): `GET /api/v1/users/:user_id/page_views` supports `start_time` and `end_time`. Fields include `id` (string), `created_at`, `url`, `context_type`, `asset_type`, `controller`, `action`, `interaction_seconds`, `participated`, `user_request`, `session_id`, `remote_ip`, `user_agent`, `links`. Privileged access and separate beta async query interfaces must be evaluated independently.
- The official Page Views disclaimer explicitly warns that log-derived data can be incomplete, duplicated, corrected later, and unsuitable for isolated high-stakes analysis of an individual or small sample. **Do not use page views alone for attendance, disciplinary action, or a definitive missing-engagement label.** `interaction_seconds` and enrollment `total_activity_time` are not interchangeable with verified active study time.
- Activity streams and todo lists are caller-specific product views, not an exhaustive engagement event feed. Missing events are not proof of inactivity; an offline learner can have legitimate activity outside Canvas.

### Pagination, History, And Access

1. Follow the opaque `Link` header's `rel="next"` URL until absent. [Official pagination](https://developerdocs.instructure.com/services/canvas/basics/file.pagination.md) states a default of 10 items and an unspecified maximum for `per_page`; do not assume 100 exhausts a list or manufacture page numbers. Never forward bearer credentials to a different host from an unvalidated next link.
2. Request only the documented OAuth URL scopes, with an authorized role and account/course visibility. Token scope is necessary but does not grant missing institutional permissions. SIS fields, hidden grades, concluded courses, anonymous graders, and account-wide users can have additional restrictions.
3. Handle [request throttling](https://developerdocs.instructure.com/services/canvas/basics/file.throttling.md) with bounded concurrency and backoff. Capture status, endpoint, page boundaries, retries, and errors without logging tokens. Do not interpret a 401/403, a failed page, or an omitted include as a valid empty dataset.
4. There is no universal REST change-data-capture cursor for these objects. Use endpoint-specific supported time filters where documented, overlap recent windows for late corrections, and reconcile full key sets periodically. A submission timestamp watermark misses a later regrade; a course inventory has no universal modification timestamp in the declared model.
5. Preserve extraction time separately from source-created, source-modified, submitted, graded, posted, and event times. When a source-modified timestamp is absent, record it as unavailable; do not relabel extraction time as a verified source modification.
6. Snapshot assignment audiences, group memberships, cross-list mappings, due dates, grading settings, enrollment state, completion, and course totals. Current APIs do not reconstruct every prior configuration or deleted record. Record tombstones and distinguish deletions from permission loss through controlled reconciliation.
7. No universal numeric retention period was established for submissions, page views, grade audit, or beta queries. Obtain the tenant's documented product-specific retention, earliest retrievable date, correction window, deletion behavior, and contractual access. Canvas Data/DAP and live-event feeds are separate potential interfaces: neither their entitlement nor their schema was pulled in this task.

### Proposed Model Additions

- **Assignment / LearningActivity**: base dates, points, grading and submission types, assignment group, publish/posting policy, source state, external-tool identity, version.
- **AssignmentAudience / AssignmentOverride / GroupMembershipHistory**: target kind, target ID, effective dates, source override ID, membership effective time, and per-student resolved due date. The single `LearningContent.DueDate` cannot represent this.
- **SubmissionAttempt / GradeRevision / CourseGradeSnapshot**: source attempt, observed version, score and display grade, denominator, excused/missing/late policy, grader kind, posted time, group attribution, grading period, and source totals.
- **AssessmentAdministration / AssessmentResultComponent**: distinguish definition, attempt event, quiz item/criterion/outcome, original score, regrade, and aggregate result. Do not conflate classroom grades with standardized growth measures.
- **LearningStandard / ContentStandardAlignment**: source taxonomy/context, external identifier, hierarchy/version, alignment type, artifact/criterion linkage, and mastery calculation. A single `StandardCode` cannot express many-to-many alignment.
- **ContentVersion / ContentPlacement / CompletionSnapshot / EngagementGrain**: preserve revisions, module placement, student-specific completion rules, and event versus daily/course aggregate provenance.
- **Governance and remaining sources**: SIS calendar/attendance, demographics, verified guardianship and accommodations, intervention ownership/outcomes, legal basis, consent/suppression, and lineage remain separate needs. Do not substitute activity logs for these gaps.

## Corrections, Blockers, And Validation

- Existing guides remain unchanged. Their combined `users.csv / User`, `terms.csv / Term`, and enrollment field lists should not be used as one extraction schema: inbound and outbound fields differ.
- The prior caution about general Submission identity is supported: the documented object has no `id` property and its URL uses the student ID. Classic `QuizSubmission` does have its own `id`; preserve the distinction.
- Prior "direct" engagement coverage is structural only. The official page-view disclaimer, caller-specific activity streams, uncertain retention, and student-context completion materially limit its analytical fitness.
- Subject, grade level, credit, demographic data, school geography, primary teacher, and normalized standards are not guaranteed simply because a course/user/assignment object exists. Existing coverage percentages are not verified schema completeness or tenant access scores.
- Some resource requests without an explicit user agent returned HTTP 403; the same needed pages succeeded using `User-Agent: education-schema-research`. Wrong/placeholder routes such as `/basics/file.sis_csv.md`, `new_quizzes_quiz_items.md`, and `course_progress.md` can return short navigation pages with HTTP 200; they were not accepted as schema evidence. Canonical content URLs were found through the official [documentation index](https://developerdocs.instructure.com/llms.txt).
- `/doc/api/api-docs/assignments.json` returned 404. The successful Swagger index points to sibling resource files such as [assignments.json](https://canvas.instructure.com/doc/api/assignments.json), not that nested path.
- Validation performed: all 144 indexed Swagger documents parsed; all 17 SIS field tables parsed; CSV uniqueness/round-trip/interface boundaries checked; `Submission` and `AssignmentOverride` properties re-compared directly with official JSON; Submission's 31 Markdown and Swagger fields matched. All checks were public-source checks, not tenant API tests.
- Blockers remaining: no token, no tenant extraction, no licensed data-product verification, no deployed-version comparison, and no historical completeness or privacy approval. The public research establishes a connector design baseline, not production readiness.
